# 分析任务、个人模板与历史资料范围

适用版本：WeChat2AI v0.1.0 / build 1。任务由用户交给所选 Agent 后自行发送；应用不调用模型，不判断分析是否完成。

## 可选择的任务

| 任务 | 输出要求 |
|---|---|
| 总结聊天 | 核心话题、结论、待确认事项，区分观点与事实 |
| 提取待办 | 事项、负责人、时间与原文依据；未提及字段写未明确 |
| 整理链接 | 链接及上下文，不编造缺失 URL |
| 仅复制记录 | 复制正文；交给所选 Agent 时先阅读范围并等待用户补充要求 |
| 发现需求与产品机会 | 用户、场景、痛点、现有解决方式、机会假设和验证问题 |
| 提炼知识笔记 | 概念、方法、案例、适用条件、注意事项与待核实说法 |
| 梳理观点与争议 | 各方主张、依据、共识、分歧和未解决问题 |
| 提取资源清单 | 工具、产品、项目、文章、课程、用途与推荐理由；不限于有链接的资源 |
| 对比新增变化 | 本批与明确选择的同群批次之间的新增、重复、观点变化及矛盾 |
| 更新项目结论 | 结合选定资料提出保留、新增、修订、撤回的结论与待验证问题 |
| 整理产品需求 | 产品需求草案：背景目标、用户场景、需求条目、流程、业务规则、边界、验收条件和待确认事项 |
| 自定义任务 | 用户填写分析要求，可仅本次使用或保存个人模板 |

「整理产品需求」尤其区分已明确同意、个人建议、存在分歧与分析推导。条目附编号、发言人与时间依据；未讨论的优先级、负责人、排期和指标不能补成事实，分析补充的验收建议须单列。群聊不会被直接包装成已批准 PRD。

## 使用与保存模板

- 在分组任务菜单选择内置任务，直接交给所选 Agent，或点击旁边「编辑任务要求…」查看和编辑要求。
- 选择「自定义任务…」会打开编辑窗口。名称最多 80 字，要求最多 4,000 字。
- 勾选「保存为个人模板」后，菜单的「我的模板」分组增加该模板。选择已保存模板再编辑并保存，会更新该模板，不修改内置模板。
- 开启「设为‘来源名’的默认任务」后，下次切换到该群或重启后重新选择该群，会恢复默认任务。自定义要求设为默认时同时保存为模板。
- 原本为默认任务时，关闭同一开关即清除绑定；要求与名称实时显示字数，错误只在底部显示。
- 设置 › 任务与 Agent 可编辑、改名和删除个人模板，清除来源默认。删除确认写明模板名与受影响的默认关联数，确认后清除这些关联，资料文件不删除。
- 个人模板和默认关联保存在应用数据目录的 `task-settings.json`。默认以资料库 ID + 来源 ID 关联，同名群或其他资料库互不影响，群改名不丢失关联。
- 编辑内置历史分析任务后保存的模板仍保留对应的范围选择流程；普通自定义任务默认只处理本批。

## 历史分析的范围

「对比新增变化」要求主批次已经归群，且至少勾选一个同群的其他批次。当前批次不能再次作为参考，也不能从其他群混入。

「更新项目结论」可以选择同群其他批次，以及该群项目 `results/` 根目录中的 `.md`、`.txt` 文件。默认均不勾选，没有已有成果时可生成结论初稿。暂不递归枚举成果子目录，也不解析 PDF 或 Word 成果。

参考资料合计最多 20 项，单份成果最大 20 MiB，整个交接包累计最多 512 MiB、10,000 项。目录离线、无效路径、符号链接、复制期间内容变化或超限会报错，不继续打开 Agent。

导入时间不等于聊天发生时间，不同导出可能重叠。Prompt 明确要求判断重复与时间范围，不能将主批次所有消息都当作新增。

## 数据副本与 Prompt

```text
<群项目>/wechat-imports/<handoffID>/
├── manifest.json / transcript.md / messages.jsonl / original/
├── handoff.json                      # 主批次、整体范围与文件散列
├── task.json                         # 选定任务、主批次 ID、参考路径、输出策略
└── context/
    ├── history/<referenceHandoffID>/ # 仅勾选的历史批次完整副本
    └── results/<编号>-<文件名>        # 仅勾选的成果文件副本
```

主批次仍是本次分析对象。参考路径相对 task.json 所在目录；Prompt 指定该文件绝对路径，并限制使用 references 中列出的资料。勾选历史后，handoff 的范围是 `primary-with-selected-context`，不会再声称“只包含一批”。没有参考时仍为 `single-batch`。

每次准备新副本；复制后原批次改归、原成果文件继续编辑，都不改变已交接内容。准备失败只清理本次新建的交接包，原资料、其他交接和用户成果保留。

一般任务「复制给 AI」继续复制本批正文、要求和原资料路径。历史分析任务的复制操作会先生成稳定资料副本，再复制任务与路径；不会把所有历史正文塞进剪贴板。其他 AI 无本机文件访问能力时，需要用户自行附加这些文件。

「更新项目结论」默认只在回复中给更新建议，写入或覆盖项目文件前由用户在所选 Agent 确认。WeChat2AI 不执行文件改写，也不以会话成功打开代表分析完成。用户仍可在所选 Agent 发送前编辑完整任务。

## 目标选择与验证边界

Codex、Claude Code、Claude Cowork 是三个独立单选目标，选择保存在 `selectedDesktopAgent` 偏好中。模板与参考范围不随目标分裂；Claude 长预填会缩短为读取完整 task.json 的要求。

交接详情保留本次任务、主批次、参考清单、提醒和副本路径。打开失败后可从详情复制已保留副本的任务，不受当前任务切换影响。任务菜单按常用、深度分析、需要历史参考、其他和个人模板分组，并标记来源默认任务。

自动测试覆盖选定历史资料的稳定副本、跨群 / 重复 / 空范围拒绝与失败清理、成果副本、越界 / 符号链接 / 大文件拒绝、模板与来源默认持久化和损坏保护。当前执行结果见[验证记录](validation.md)。

任务模板是分析引导，不保证模型输出完全符合结构。真实需求整理质量、跨批次分析准确性、成果写入、客户端目录确认、权限及最终读取，仍需用户在所选 Agent 中实际验收，见[产品约定](product-contract.md)。
