# WeChat2AI 全局 Theme 与交互 UX 规范

版本：1.0 · 更新日期：2026-11-14 · 主题：Editorial Sandstone（暖岩与手稿灰）。

适用范围：原生 macOS 13+ 主窗口、Sheet、接收管理、任务编辑和正文预览。SwiftUI 为唯一主界面，AppKit 提供系统窗口、面板和文本桥接。本规范描述当前设计约束；实际检查结果与未覆盖范围见[验证记录](../validation.md)。

## 1. 依据与设计取舍

- 业务与权限依据：[架构](../architecture.md)、[分析任务](../analysis-tasks.md)、[产品约定](../product-contract.md)、[隐私说明](../../PRIVACY.md)。
- 共享实现：`App/W2ATheme.swift`、`App/W2AComponents.swift`；品牌来源与许可见 [NOTICE](../../NOTICE.md)。
- 主按钮使用黑白反转；陶土色承担选择、焦点和品牌细节。持续选中与瞬时按下使用不同状态。
- 界面显示运行时真实身份、统计和路径，不添加推测的数据、头像、进度百分比或未实现功能。
- 当前任务为单选，历史参考必须显式选择，附件按完整批次交接。全局搜索、知识库导航和逐附件勾选均需独立需求。
- 请求打开 Agent 不表示已读取或分析；选择、按钮、交接结果始终引用同一目标，由用户确认发送。

## 2. 产品与视觉原则

核心任务：把微信分享或手动导入的资料保存在本机，按群或对话归档，明确选择任务与资料范围，再交给外部 Agent，由用户在目标应用确认发送。

- **阅读优先**：暖白阅读画布、克制的分隔与舒适行距；长正文是工作区主体。
- **归档有层次**：资料库 → 来源 → 导入批次 → 原文及附件，身份和路径均来自真实数据。
- **强调有含义**：灰阶承担结构，陶土色承担选择与焦点，状态色承担结果；颜色同时配合文字或图标。
- **操作有反馈**：导入、读取、保存、打包和打开客户端各自有明确状态及恢复入口。
- **原生且安静**：使用系统字体、窗口、文件面板、菜单和键盘惯例；不把宣传图的砂岩摄影、噪点或大面积渐变搬进工作区。
- **范围可追溯**：始终能知道当前资料库、来源、主批次、任务和目标 Agent；历史参考须明确选择。

## 3. 全局 Theme Token

### 3.1 命名与落地

以下名称采用统一的 `w2a` 语义命名。原生实现统一由 Theme 层或 Asset Catalog 提供浅深色值，例如将 `bg-canvas` 映射为 `W2ATheme.Colors.canvas`。对应实现已集中在 `App/W2ATheme.swift` 与 `App/W2AComponents.swift`。

视图不得散落 Hex、裸 RGB 或临时的系统蓝/红/橙色。系统文件面板、窗口装饰等由 macOS 管理的部分遵循系统外观；自有组件使用统一 Token。外观默认跟随系统，当前不因此增加独立主题设置。

### 3.5 字体与阅读

所有尺寸在原生界面中按逻辑 pt 定义，Retina 像素由系统处理。

| 用途 | 字号 / 字重 | 规则 |
| --- | --- | --- |
| 窗口内容标题、批次标题 | 15pt / Semibold | 不修改系统标题栏字号；长标题可截断并提供完整信息 |
| 分区标题、来源行、按钮 | 12pt / Medium | 标签清楚，按钮不只靠图标 |
| 聊天正文 | 14pt / Regular | 行高 23pt；阅读视图每条消息后 14pt，原文段距 8pt |
| 时间、批次标识、文件大小 | 11pt / Regular | 数字等宽；不得靠过浅颜色弱化 |
| 空状态、交接 Sheet 标题 | 18pt / Semibold | 一句说明当前状态 |

- 中文采用系统中文字体回退（PingFang SC），拉丁文字采用系统 SF；使用系统字体 API，不依赖下载字体。
- 连续数字使用等宽数字；代码、文件内容和交接负载可使用系统等宽字体。普通说明不使用装饰性的等宽字。
- 宋体只可用于宣传资产的短句；正文、控件和操作说明保持系统无衬线字体。
- 阅读列目标约 60–68 个拉丁字符宽，中文以实际字面宽度核验，不能解释为 68 个汉字。宽窗口增加阅读区留白，不无限拉长正文行。
- 正文保留原始换行、顺序和未知字段；长 URL、代码及文件名允许在专用内容区域横向滚动或换行，不撑开整个窗口。

阅读视图由同批 `messages.jsonl` 排版：发言人 12pt Semibold、时间 11pt 等宽数字，头行 18pt，正文保留消息内换行；单行消息占约 55pt。默认使用阅读视图，原文视图展示 `transcript.md`。原文回退、消息数为零或 JSONL 不可用时显示原文并说明；有未解析内容时提示核对原文。正文选区复制当前可见文字，“复制给 AI”和交接仍使用原 Markdown 及所选资料范围，不以屏幕排版替换文件。图片消息在文件名下显示本机缩略图，保持比例、最大 420 × 280pt；单图不放大超过解码尺寸。只解码视口附近图片，后台按实际文件类型检查、校正方向并下采样到最长边 1024px；单图最大 32 MiB、原图最大 1 亿像素，GIF 等多帧格式仅显示首帧。内存缓存预算 24 MiB（另有可见位图和正在解码的瞬时内存），离屏单元释放位图，切批次丢弃过期结果。图片缺失、损坏、不支持或超限时显示说明并保留文件入口，不阻止正文阅读。附件文件名只定位经路径与符号链接校验的本批文件；缺失附件不提供可点击定位。

### 3.6 间距、圆角、线条与阴影

| 类型 | Token / 数值 | 用途 |
| --- | --- | --- |
| 间距 | `space-1…6` = 4 / 8 / 12 / 16 / 20 / 24pt | 图标与文字 4–8；组件间 8–12；区块内边距 16；Sheet 内边距 24 |
| 小圆角 | `radius-sm` = 5pt | 附件芯片、微型状态标签 |
| 控件圆角 | `radius-md` = 6pt | 按钮、输入框、分段容器 |
| 卡片圆角 | `radius-lg` = 8pt | 导入批次、附件卡片 |
| 大圆角 | `radius-xl` = 12pt | 自有面板内部容器；系统窗口与 Sheet 外壳由 macOS 决定 |
| 标签圆角 | `radius-pill` = 容器高度的一半 | 仅用于独立状态标签或任务胶囊；不把普通按钮全部做成胶囊 |
| 标准线 | 1pt | 分隔与描边；细分隔可用按 backing scale 对齐的 1 物理像素线 |
| 选择线 | 1.5pt 描边 + 3pt 左标记 | 批次选中；预留空间，切换时不改变卡片尺寸 |

浅色卡片阴影定义为：`(0,1,2,rgba(28,25,23,0.05))` 加一层 1pt、4% 炭黑轮廓；浮层为 `(0,12,32,rgba(28,25,23,0.14))` 与 `(0,2,6,rgba(28,25,23,0.08))`。元组表示水平偏移、垂直偏移、模糊及颜色，原生渲染按视觉效果校准，不要求 CSS 与 AppKit 模糊算法逐像素相同。

深色以边界和表面层级为主，阴影仅辅助分离；系统 Sheet、Popover 使用系统投影，避免重复加阴影。嵌套圆角的子容器不大于父容器圆角。

## 4. 窗口、布局与缩放

### 4.1 信息结构

```text
窗口标题栏 / 资料库及工具区
├─ 来源侧栏          ├─ 导入批次列表        ├─ 当前批次详情
│  待分类            │  来源标题 / 数量     │  来源、时间、统计与警告
│  群 / 对话         │  当前批次            │  正文预览 / 附件入口
│  群 / 对话         │  历史批次            │  阅读滚动区域
│  新建来源          │                    ├─ Agent 交接台
│                   │                    │  任务、参考范围、目标、操作
└───────────────────┴────────────────────┴─ 状态摘要及完整信息入口
```

此结构已由 SwiftUI 主界面实现；操作入口覆盖待分类、新建、改名、改归、资料库管理、任务模板和接收恢复入口。当前不增加独立“AI 任务”或“知识库”导航模块。设置使用独立、非模态的原生窗口（⌘,），包含通用、资料库与数据、接收、任务与 Agent 四页，与主窗口共用模型和操作锁。

工具区将资料库管理和应用设置分开：资料库名称带可见下拉箭头，菜单只承载资料库信息、打开、新建、Finder和刷新；应用设置以齿轮加“设置”文字独立显示，默认及最小窗口均保持可见。它复用原设置窗口，保留应用菜单“设置…”与⌘,，不增加另一套设置或改变忙碌/面板互斥规则。

### 4.2 布局参数

| 项目 | 目标值（内容区逻辑 pt） | 约束 |
| --- | --- | --- |
| 初始窗口 | 1180 × 760 | 当前共享 Token，系统标题栏另计 |
| 最小窗口 | 960 × 620 | 当前内容最小尺寸；窄窗口收起来源以保留交接入口 |
| 工具内容区 | 高 52 | 不包含系统标题栏，不以手绘红黄绿按钮替代原生控件 |
| 来源栏 | 最小 200 / 理想 220 / 最大 260 | 按窗口宽度协调或收起 |
| 批次栏 | 最小 260 / 理想 280 / 最大 320 | 独立纵向滚动 |
| 阅读区 | 剩余宽度，下限 620 | 不足时收起来源；正文列最大 680 |
| 详情头 | 高 72 | 两行，低频文件操作进入 ⋯ 菜单 |
| 交接台 | 高 92 | 两行，主按钮内部标签最小宽 132 |
| 状态条 | 高 28 | 单行摘要与“详情” |

当前实现：`W2ATheme.Layout` 共享初始与最小内容尺寸；系统标题栏另计。工具区 52、详情头 72、交接台 92、状态条 28 与四条 1pt 分隔线，固定合计 248pt。正常阅读区在 960 × 620 下目标为 372pt，在 1180 × 760 下为 512pt；回退或未解析提示会占用额外 24 / 28pt。来源与批次栏按比例在上表范围协调，缩至下限后阅读区仍不足 620pt 则收起来源。窄窗口保留来源浮层及顶部来源 Picker；收起偏好持久化。字标在宽度不足 1040pt 时隐藏。工具区显示路径推导的资料库名，待处理接收仅在有任务或错误时出现。

### 4.3 窄窗口与长内容

- 以可用空间决定是否收起来源栏；来源宽 220、批次宽 280 挤压阅读区时，先缩至各自下限，再收起来源。提供始终可见的恢复入口，并保留当前来源名称。
- 关键流程保持“选批次 → 读正文 → 设任务 → 交给 Agent”。常用主按钮保持可见；低频的分享、群项目、库管理可进入具名菜单。
- 三个 Agent 名称完整显示；空间不足改用原生 Picker，不截断为难辨识的缩写。
- 标题、状态和路径采用限定行数及截断；完整信息通过可访问的详情、选择复制或菜单查看，不能只靠鼠标 Tooltip。
- 正文和批次独立滚动。交接台不随长正文滚出视口；高度不足时把配置放入 Sheet，保留任务摘要和主操作。
- 工具区和状态条的高度在加载、错误、成功之间稳定。长错误放在详情区，摘要不撑开顶部或底部。
- 面板宽度应受父窗口可用内容宽度约束；操作区可合理分行。不得出现整个窗口横向溢出、控件覆盖或按钮脱离边界。
- 本期是 macOS 窗口规范，不增加手机端断点或新平台需求。

## 5. 组件与状态规范

### 5.1 公共状态

| 状态 | 视觉与交互 |
| --- | --- |
| Default | 使用所属表面、标准描边及可读标签 |
| Hover | 在原底上叠加 `bg-subtle-hover` 或采用主按钮 Hover Token；不降低文字可读性 |
| Pressed | 主按钮使用 `primary-active`，次按钮加深反馈；释放后回到 Default / Hover |
| Selected | `bg-selected`、陶土色描边及标记；仅用于持续选择，不代表键盘焦点 |
| Focused | 2pt 陶土色轮廓及 2pt 外偏移；与 Selected 叠加时两者可分辨 |
| Disabled | 默认透明度 0.4，批次卡片 0.45；移除动作能力，并在邻近提示或辅助说明中提供原因 |
| Loading | 进度指示 + 明确阶段；重复触发被拦截，不能继续点击创建重复任务 |
| Error / Warning | 语义图标、文字和恢复入口；重要说明可选择复制 |

透明度仅用于禁用控件，不用于弱化正文或仍需用户理解的禁用原因。视觉层的禁用不能代替模型和操作入口的状态校验。

### 5.2 各组件约定

| 组件 | 结构与行为 |
| --- | --- |
| 主按钮 | 当前区域仅一个最高优先级动作；主交接区标签为“交给 {Agent}”，仅在交接准备 / 请求打开时显示“正在准备…”，其他忙碌操作保留标签并禁用；高 32pt |
| 次按钮 | `bg-elevated` 或所在表面、`border-strong`、`text-primary`；复制、Finder 和关闭不与主操作争夺视觉权重 |
| 来源行 | 图标、来源名称及有明确定义的计数；名称与备注均相同时附短 ID；备注在 Tooltip 与归档面板查看，选择高亮不能只改变文字颜色 |
| 批次卡片 | 两行固定 56pt、间距 6pt：聊天起止时间；条数、附件数和简短导入时间。ID 在详情、信息面板、右键复制入口查看；选中用 1.5pt 陶土描边和 3pt 左标记，避免状态切换导致跳动 |
| 任务选择 | 当前能力为单选；菜单按常用、深度分析、需要历史参考、其他及个人模板分组，保留“编辑任务要求…”和“管理模板…”入口；来源默认任务有标记；不照抄图片中的多个任务复选框 |
| Agent 选择 | 单选 Codex、Claude Code、Claude Cowork；阅读列宽 ≥ 700pt 使用分段，否则菜单；选择状态、按钮名称、交接结果保持一致 |
| 输入与编辑 | 有可见标签、合理默认值、字段级错误；错误不清空输入，取消不写入模板或群默认 |
| 正文预览 | 支持中文选择、复制、全选及键盘滚动；指示延后 150ms，避免快速读取闪现；新批次立即清空旧正文，不能把上一批正文当作新批次内容 |
| 状态条 | 图标、单行摘要、完整信息入口；“已保存本机”与“已请求打开 Agent”分别说明 |
| Sheet | 绑定父窗口，同一时刻一个；有明确标题、主操作与取消，草稿提交前不改变原设置 |
| 接收任务行 | 展示队列状态、接收身份、目标库和原因入口；接收 ID 不冒充已提交的批次 ID |
| 附件入口 | 阅读视图图片消息显示等比例本机缩略图，文件行可定位 Finder，详情 ⋯ 保留 Finder / 分享原件；缺失、不可读和未解析项如实标识，不生成虚构预览 |

交互热区建议不小于 28 × 28pt，紧凑图标按钮至少通过内边距扩展热区；原生窗口控件遵循系统尺寸。主操作建议高 32pt，行内控件建议高 28pt，避免为了紧凑而降低可操作性。

## 6. 核心流程与 UX 规则

### 6.1 首次使用、资料库与空状态

1. 有效资料库但没有批次：说明“尚无导入的聊天批次”，主入口为“导入聊天记录”，辅以微信分享步骤与“连接接收目录…”说明。
2. 微信分享流程按真实行为说明：多选消息 → 合并转发 → 转发到其他应用 → WeChat2AI。首次授权和分享扩展启用方法提供简短帮助。
3. 已有资料但当前来源为空：只提示该来源无批次，不重复展示全套安装引导。
4. 已保存的资料库离线、缺失或无权限：展示真实错误及重新打开 / 连接入口。不得呈现为“新用户空库”或静默新建替代库。
5. 切换库时按资料库 ID 隔离来源、默认任务和批次选择；显示当前资料库名称与可查看的真实路径。

### 6.2 导入、接收及恢复

导入阶段显示“接收中 / 等待导入 / 正在解析 / 正在保存 / 已入库 / 需要处理”等真实状态。队列依据保持 `incoming → ready → processing → completed`，失败进入 `failed`；界面显示中文语义，不因重绘而改写协议。

| 场景 | 必须表达 | 可用行动及边界 |
| --- | --- | --- |
| 接收中 | 接收尚未完整，尚未形成可用批次 | 不把关闭面板当作取消接收；不能提前重试未完整 payload |
| 解析 / 写入中 | 当前阶段、目标资料库、忙碌指示 | 锁定会改变写入目标的相关操作；不阻塞主线程 |
| 有真实计数 | 已处理 / 总数或实际进度 | 只有总量可靠时显示百分比；图片中的 68% 不是固定值 |
| 仅阶段可知 | 阶段文字及不定进度 | 不通过计时伪造百分比或完成时间 |
| 正文可用、存在缺失附件或解析警告 | 已保存内容、未保存内容及原因 | 保留原文和警告；用户仍能检查资料及明确决定是否交接 |
| 导入失败 | 本次未完成、具体原因、原数据保留情况 | 按现有能力提供重试、另存接收包、Finder、重新连接等 |
| 已入库但暂存清理失败 | “已入库，暂存清理未完成” | 重试依据回执恢复，不创建重复批次 |
| 需要丢弃 | 将丢弃哪个接收包及范围 | 显式确认；不要把丢弃暂存包说成删除所有资料副本 |

“取消导入”“仅保留已解析正文”需要实际的取消或部分提交机制后才能启用。当前没有对应能力时使用已有恢复流程；不得为了贴合示意图添加无效按钮。成功入库并写入回执后才清理接收 payload；手动导入的原文件不被清理。

### 6.3 来源、批次、归档与正文

- 新批次默认进入“待分类”；归档由用户选择现有来源或新建来源，不从聊天内容推断真实群身份。
- 归档 / 改归前明确目标来源；改名改变展示名，保持稳定身份，不能据此改写历史引用。
- 刷新后按稳定批次 ID 恢复有效选择；选择消失时回退至有效项或空状态，不能留下旧批次详情。
- 切换批次时更新元信息并显示读取状态；异步读取完成后核对请求 ID 和批次 ID，丢弃过期结果。切换批次可重置正文滚动，同批次状态更新不重置阅读位置。
- 导入时间与聊天时间分开标明；来源未提供时区时显示未知，不自动补造本地时区。相对日期应能查看完整日期。
- `Batch #042` 等是示例，不要求重建连续序号。显示真实批次标识或清楚标注的缩略 ID，完整 ID 可查。
- 当前批次列表按已有数据规则展示；未实现排序控件前不显示可点击的“按时间倒序”菜单。
- 不自动去重，不将重复导入当作新增内容已去重；头像、成员人数、附件页数或媒体时长均须有真实数据支持。

导入时间按当前本地日显示“今天 HH:mm”、同年“MM-dd HH:mm”、跨年“yyyy-MM-dd HH:mm”，完整时间在批次信息可查。聊天起止时间采用导出文件的本地时间，不补时区；同一天省略终点日期，无时间显示“未识别聊天时间”。

归档使用路由内 SwiftUI Sheet，超过 8 个来源可筛选，可新建来源；未选目标或与当前归属相同时不能确认。导入后默认询问，也可在设置选择先放入待分类；取消归档不误消费下一项接收。批次拖放到来源时校验资料库身份及批次存在，再调用相同归档操作。按资料库 ID 恢复有效来源与批次；失效选择回退。

### 6.4 任务、模板与历史参考

- 当前一次交接只有一个任务；任务名称、指令及输出要求使用[任务文档](../analysis-tasks.md)的真实定义。
- 自定义名称最多 80 字、要求最多 4,000 字；校验失败保留草稿并提示具体字段。取消不保存，提交成功后才更新模板和默认关联。
- 默认任务使用单一开关，原本为默认时关闭即清除；设置 › 任务与 Agent 可管理、改名和删除个人模板，删除确认说明受影响的默认关联数，并一并清除这些关联；默认任务以资料库 ID + 来源 ID 绑定，同名来源不得串用。
- 普通任务明确为当前批次。历史任务进入参考范围选择，不因同属一个来源而默认纳入全部历史。
- “对比新增变化”要求已归群并至少选择一个同群其他批次；当前批次不能同时作为参考，禁止跨群引用。
- “更新项目结论”可选择同群历史及群项目 `results/` 根目录的 `.md`、`.txt`，默认均不选；无历史成果时允许生成初稿。
- 参考合计最多 20 项、单份成果最大 20 MiB、交接包最多 512 MiB / 10,000 项；在提交前解释超限或失效项，不能静默裁剪范围。
- 列表提供“全选”时，同时提供相同范围的“取消全选”，支持部分选择状态与已选计数；不让全选跨越当前可见或明确声明的范围。

### 6.5 Agent 交接与复制

默认路径为：检查批次与任务 → 必要时选择参考 → 生成并校验稳定副本 → 请求打开所选客户端 → 用户在目标应用检查并发送。普通交接不强制增加新的确认步骤；若引入资料范围预览，应清晰区分准备前范围与准备后结果。

| 状态 | 建议文案与行为 |
| --- | --- |
| 无可用批次 / 正文读取失败 | 禁用交接与复制，并提供选择批次或读取失败的原因 |
| 正在准备 | “正在准备分析任务与选定资料…”；禁止重复提交，使用本次捕获的库、批次、任务及 Agent 快照 |
| 客户端未安装 | “未找到 {Agent} 桌面端，可使用‘复制给 AI’。”；保留当前目标，不自动换 Agent |
| 副本准备失败 | 显示原因，保留原批次、已有交接及成果；只清理本次未完成的新副本 |
| 已发出打开请求 | “已请求打开 {Agent} 并预填‘{任务}’。请确认目录、检查任务并自行发送。”；不声称已读取或分析完成 |
| 客户端打开失败 | 明确副本是否已保留，并提供复制及查看目录入口 |
| 普通任务复制成功 | “已复制任务与本批文字。图片和文件需在 AI 应用中另行添加。” |
| 历史任务复制成功 | “已复制任务与选定资料的稳定路径。历史资料和成果已保存副本；未启动分析。” |

本批最近交接结果保存在内存，切换来源、批次和资料库后返回仍可查看；不承诺重启恢复。应用激活和切换 Agent 时预先检测客户端，不存在时提示复制替代。

交接结果或详情应能查看目标 Agent、任务、主批次、选定参考、警告和真实副本路径。不会把整库自动纳入上下文。原批次后续改归不移动已生成的独立副本；这些副本仍可能被用户或外部程序修改，不宣称其不可变或加密。

使用“重新交给 {Agent}”等表述时，说明是在重新准备 / 请求打开；不得暗示 WeChat2AI 能直接发送消息。聊天和附件属于分析资料，不是执行指令；更新成果的写入或覆盖由用户在目标 Agent 中确认。

## 7. 文案、键盘与反馈

### 7.1 术语与提示

| 术语 | 统一含义 |
| --- | --- |
| 资料库 | 当前打开的本地归档容器 |
| 来源 / 群或对话 | 用户指定的归档身份，不保证是从微信自动识别的群 |
| 导入批次 | 每次导入的独立记录，不与接收暂存任务混称 |
| 待处理接收 | 接收队列中的未完成项目，不与导入批次混称 |
| 编辑任务要求 | 本次要求与模板草稿，区别于应用“设置” |
| 任务 | 本次交给 Agent 的分析要求；不等于分析正在执行 |
| 交接副本 | 为外部 Agent 准备的独立资料副本 |
| 交给 Agent | 准备资料并请求打开客户端，最终发送由用户执行 |

操作使用具体动词：“导入聊天记录”“归档 / 改归”“复制给 AI”“在 Finder 中查看”。中文界面保留 Codex、Claude Code、Claude Cowork 的完整名称。错误格式为“发生了什么 + 保留了什么 + 可以怎样恢复”，避免单独显示“失败”或暴露无解释的内部异常。

### 7.2 键盘与辅助操作

- 应用：⌘, 设置、⌘H 隐藏、⌥⌘H 隐藏其他、⌘Q 退出。文件：⌘O 导入、⌘N 新建来源、⇧⌘O 打开资料库、⌘W 关闭窗口。
- 编辑：⌘Z / ⇧⌘Z 撤销 / 重做，⌘X / ⌘C / ⌘V / ⌘A 按焦点剪切 / 复制 / 粘贴 / 全选；⌘F 批内查找，⌘G / ⇧⌘G 下一个 / 上一个。
- 显示：⌃⌘S 来源侧栏、⌘1 阅读、⌘2 原文、⌘R 刷新。批次：⌘I 资料、⇧⌘R Finder。交接：⌘↩ 交给当前 Agent、⇧⌘C 复制给 AI、⌘T 编辑任务要求。窗口：⌘M 最小化。
- 业务菜单共享模型校验；⌘↩ 仅主窗口无面板且可交接时生效。正文与草稿的原生编辑命令按焦点执行，面板回车仅触发其默认操作。
- Tab / Shift-Tab 依系统完整键盘访问设置移动焦点，列表支持系统方向键选择，Space 切换复选或单选控件。
- Escape 关闭可取消的 Sheet，取消不写入草稿；Enter 只触发当前弹窗明确的默认动作，不在任务多行编辑中误触发交接。
- 丢弃等破坏性操作必须有明确对象和确认，不能设为误触即执行的默认动作。
- 忙碌或有面板时业务操作互斥；仅正文读取时允许配置与归档，交接和复制须等待有效正文；限制由模型统一控制；关闭进度面板不等于停止后台写入。退出拦截说明正在保存、读取或交接的实际原因。
- 完成反馈不随短暂 Toast 消失：当前状态保留，完整详情可查；弹窗关闭后焦点返回触发控件或合理的后继位置。

### 7.3 动效

悬停、按下和颜色过渡建议 120–150ms；局部面板出现建议 180–220ms，采用平缓减速。窗口及系统 Sheet 采用系统动效，不重复播放自定义入场。遵循系统减少动态效果设置，移除非必要位移与缩放。进度必须由真实状态驱动，不用装饰性动画模拟工作。

## 8. 可读性与无障碍验收规则

本项目将普通文字对比度至少 4.5:1、大字号文字至少 3:1、承担识别作用的控件标记 / 焦点至少 3:1 作为验收门槛。Token 和描边本身不等于已经通过；需要按最终背景、透明度合成和字号核验。

实色 Token 按相对亮度计算有以下风险示例（四舍五入到两位，非整屏无障碍认证）：

| 配色 | 对比度 | 使用规则 |
| --- | --- | --- |
| 浅色 `text-muted` / `bg-canvas` | 4.68:1 | 可用于暖白阅读区的辅助文字 |
| 浅色 `text-muted` / `bg-surface` | 4.33:1 | 11–12pt 元数据改用 `text-secondary` |
| 浅色 `text-muted` / `bg-sidebar` | 3.89:1 | 侧栏时间与统计改用 `text-secondary` |
| 深色 `text-muted` / `bg-elevated` | 4.29:1 | 浮层辅助文字改用 `text-secondary` |
| 浅色 `status-warning` / `status-warning-bg` | 3.22:1 | 使用状态图标加主文字，不用于小字号警告正文 |

- 关键状态至少有文字或形状变化；选中、错误、缺失附件不能只改变颜色。
- 图标按钮提供可读名称，列表项可读出来源 / 批次、统计及选中状态；装饰图标不重复朗读。
- 禁用原因、完整错误和关键路径有可键盘访问的查看方式；Tooltip 只作为补充。
- 支持 VoiceOver、系统增加对比度与降低透明度设置；原生材料失效时退回实色表面。
- 在最小窗口、浅深色、长中文名称、长路径、大正文及系统文字显示调整下核验布局；不能靠缩小正文或隐藏主操作解决溢出。

| 能力 / 项目 | 当前依据 | 设计落地规则 |
| --- | --- | --- |

| PDF / SQL 内联预览、图片放大查看与逐附件勾选 | 尚未实现 | 后续独立需求；不得声称只交接勾选附件 |
| 确定百分比、取消导入、仅提交已解析正文 | 尚需相应底层机制 | 当前使用真实阶段和已有失败恢复入口 |
| 成员头像、人数及聊天全文结构化展示 | 示意数据不代表已解析字段 | 仅展示实际可靠字段，不从图片推导业务数据 |
| OCR、转写、自动去重、自动群识别、自动脱敏、云同步或自动 AI 分析 | 当前限制或超出本期 | 不作为主题改造隐含需求 |

逐附件选择若在后续实现：需要明确默认范围、全选 / 取消全选、缺失项、已选数量和体积；选择必须真实影响交接包和清单，而不只是改变勾选外观。附件缺失时保留引用和警告，不伪装为已打包。

## 11. 实施与验收清单

### 11.1 开发约束

- Theme 层集中定义颜色、字体、尺寸和状态样式；SwiftUI 与 AppKit 桥接使用同一语义映射。新 Token 先补充本规范，避免页面私有色板。
- 视图只展示状态及发出操作；文件读取、导入、归档、交接继续通过 AppModel / 操作层和 WeChat2AICore，耗时 I/O 不放在主线程。
- 忙碌、弹窗、预览加载等状态保留独立语义；操作开始捕获稳定目标，结束后恢复允许条件，继续接收队列。
- 标识、命令、格式和数据路径统一采用 WeChat2AI 产品约定。
- 验证使用隔离目录和虚构资料；主题开发、构建及 CI 不自动安装应用、注册分享扩展或向外部 Agent 发送任务。

### 11.2 视觉与交互验收

每次界面变更按以下清单检查，将实际结果与未覆盖范围写入[验证记录](../validation.md)。模拟客户端测试与真实客户端读取分开记录。清单是验收要求，不表示所有组合已经验证。

- [ ] 主窗口、Sheet 和原生桥接内容完成浅深色适配；颜色、字阶、间距、圆角和状态均来自统一 Theme。
- [ ] 在目标初始 / 最小内容尺寸 1180 × 760、960 × 620 验收，统一 NSWindow 与内容最小尺寸。
- [ ] 长群名、同名来源、长文件路径、长 URL、无正文、极长正文及多批次下无窗口横向溢出、遮挡或关键操作丢失。
- [ ] Default、Hover、Pressed、Selected、Focused、Disabled、Loading、Error / Warning 状态清楚；选中与键盘焦点能同时分辨。
- [ ] 首次空库、来源空列表、库失效、预览读取失败、部分解析 / 缺失附件、接收失败及暂存清理失败均可解释并恢复。
- [ ] 快速切批次不串正文，刷新不串选择；重复点击不产生重复交接，弹窗取消不保存草稿或误消费下一项接收任务。
- [ ] 任务与 Agent 单选语义正确；历史参考默认不选、范围与限制清楚，全选有同范围的反向操作。
- [ ] 交接准备成功、客户端打开失败及复制结果各自准确，目标名称一致；从未把打开请求标为已分析完成。
- [ ] 原文选择 / 复制 / 全选正常，键盘可完成主流程，焦点可见且关闭 Sheet 后合理返回；VoiceOver 有名称与状态。
- [ ] 文本与实际表面对比度通过第 8 节门槛，检查状态色、禁用原因、焦点及系统增加对比度 / 降低透明度 / 减少动态效果。
- [ ] 截图使用虚构资料，并记录内容尺寸、浅深色外观、UI 路径（SwiftUI 主界面）、测试场景与未验证项。

### 11.3 验证命令及记录

实现修改按以下命令验证；实际结果见[验证记录](../validation.md)：

```bash
# 核心行为发生变化
bash scripts/test.sh

# App 状态、交互或桥接逻辑发生变化
bash scripts/test-app.sh

# 确认完整原生 App 可构建
bash scripts/build.sh

# 已完成上面需要的构建后，在虚构数据与独立路径中检查 SwiftUI
bash scripts/run-ui-isolated.sh
```

本项目没有 SwiftPM test target，不以 `swift test` 代替已有测试入口。`swift build` 只覆盖核心库和 CLI。规范本身不替代执行日志及逐项验证记录。界面截图不能代替资料完整性验证，替代客户端测试不能代替真实客户端权限与最终读取验收。

相关实现结果记入[验证记录](../validation.md)，设计目标和 Token 变化更新本文，资源来源与许可更新 NOTICE。
